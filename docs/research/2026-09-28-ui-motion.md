Scope: Apple motion principles → numbers; audit of what gpui-kit 0.7.0 (`gpui-pre 0.3.7`, `gpui-base 0.7.0`, `gpui-component 0.7.0`) already provides for motion, materials, titlebars, text and system preferences; gaps dial must fill; a five-year design language; a draft rule for `.omp/rules/ui-design-motion.md`.

## 0. Summary / recommendations

1. **Don't write a spring solver.** gpui-pre 0.3.7 already ships an exact, frame-rate-independent damped-oscillator solver (`SpringConfig::step`, `step_ramp`, `settle_time`, `sampled_easing`; `src/spring.rs`). gpui-base 0.7.0 wraps it in the Apple/SwiftUI parameterisation (`Spring::new(response).with_damping(ζ)` ⇒ `m=1, k=(2π/response)², c=2ζ·2π/response`; `src/motion.rs:442-555`), and both layers keep velocity when the target changes and honor `cx.reduce_motion()`. dial-ui adds only: (a) a `const` preset table (§2), (b) an **entity-owned `AnimatedValue`** for motion that must outlive element state or accept an injected velocity (gesture release), (c) a **paint-only offset element** so moving things don't re-run layout, (d) a **reduced-motion policy** that swaps movement for a short fade instead of snapping, (e) system accent / reduce-transparency / increase-contrast readers (safe APIs, no `unsafe` in dial).
2. **Presets = Apple's numbers, in Apple's parameterisation** (perceptual duration + bounce). Default everything to bounce 0. Bounce > 0 only when a gesture throws momentum toward the target. Never exceed 0.3 in dial.
3. **Frame pacing is solved upstream.** Measured 120 Hz (8.33 ms median) with `window.request_animation_frame()` on a ProMotion Mac. Budget is therefore **≤ 4 ms of main-thread render+layout+paint per frame** while anything animates, and **≤ 8 ms** on a 60 Hz display.
4. **Materials:** default windows are **Opaque** on all platforms. Opt-in translucent chrome: macOS `Blurred` (whole-window `NSVisualEffectView`), Windows 11 22H2+ `MicaBackdrop`/`MicaAltBackdrop`, Linux `Blurred` only on KDE (`org_kde_kwin_blur`), otherwise Opaque. No native Liquid Glass (`NSGlassEffectView`) — GPUI has no hook, and adding one would need `unsafe` in dial. Approximate the glass look in-app with translucent fills, hairline highlights and shadows.
5. **Design language:** OKLCH-authored tokens (base hue, accent, contrast → generated ramps, like Linear's three-variable theme), Inter 4.1 for UI + JetBrains Mono 2.304 for code/terminal (both OFL-1.1, bundled unmodified, static weights), a 4-px spacing grid, radii 4/6/8/12, three elevations, Lucide icons at 16 px/1.5 stroke, keyboard-first with a command palette and always-visible `focus_visible` rings.
6. **Conflict to resolve:** `.omp/rules/gpui-patterns.md` says coalesce token streams to ~100 ms before `cx.notify()`. At 120 Hz that makes text arrive in visible 10 Hz steps. Recommend coalescing to **one notify per frame** (cap ~33 ms). Rely on `TextView` stream fade (280 ms, 10 ms stagger) for smoothness, and move markdown parsing off the UI thread when it exceeds budget.

## 1. Apple motion principles → numbers

### 1.1 Spring model (WWDC23 10158 "Animate with springs"; WWDC18 803 "Designing Fluid Interfaces")
- Apple has two parameterisations of the same system:
  - WWDC18: **damping ratio ζ** and **response** (the undamped period). WWDC18 avoids the word "duration" on purpose: "the spring is always moving, and it's ready to move somewhere else".
  - WWDC23: **perceptual duration d** and **bounce b ∈ [−1, 1]**.
- Conversion (mass fixed at 1). The formula as printed on the WWDC23 page has typos; this is the corrected form, confirmed by the dimensional check below and by probe values matching critical damping at b=0:
  - $m = 1,\quad k = (2\pi/d)^2,\quad \omega_0 = 2\pi/d$
  - $c = 4\pi(1-b)/d$ for $b \ge 0$;  $c = 4\pi / (d\,(1+b))$ for $b < 0$
  - hence $\zeta = c / (2\sqrt{km}) = 1-b$ for $b \ge 0$, and $1/(1+b)$ for $b<0$; response ≡ d.
  - Check: critical damping $2\sqrt{k}=4\pi/d$ ⇒ b = 0 is exactly critically damped ("smooth").
  - Peak overshoot from rest: $e^{-\pi\zeta/\sqrt{1-\zeta^2}}$.
- **gpui-base `Spring::new(response).with_damping(ζ)` is exactly this mapping** (`gpui-base-0.7.0/src/motion.rs:551-554`: `frequency = TAU / response; SpringConfig::new(frequency², 2·ζ·frequency, 1.0)`). Apple (d, b) therefore maps to `Spring::new(d).with_damping(1-b)` for b ≥ 0.
- **Settling duration ≠ perceptual duration.** Apple: settling "can be a bit unpredictable… you shouldn't wait for the settling duration for user-facing changes". SwiftUI completion handlers fire on the perceptual duration.

## 2. Proposed dial presets (Apple parameterisation, probe-computed)

All are `const` items. `Spring::new` and `Spring::with_damping` are `const fn`. An invalid literal becomes a **compile error** (probe: `const BAD = …with_damping(-1.0)` → `error[E0080]: evaluation panicked`), so no runtime panic path exists. Pixel-space springs use `.with_epsilon(0.5)` (half a pixel); normalized 0..1 springs keep the default 0.001.

| preset | d (s) | b | ζ | k | c | overshoot | settle (0→1, ε 1e-3) | use |
|---|---|---|---|---|---|---|---|---|
| `MICRO` | 0.20 | 0 | 1.00 | 986.96 | 62.83 | 0 % | 293 ms | hover/press tint, icon swaps, checkbox |
| `UI` (default) | 0.35 | 0 | 1.00 | 322.27 | 35.90 | 0 % | 514 ms | popovers, menus, palette, tabs indicator, list insert |
| `SNAPPY` | 0.30 | 0.15 | 0.85 | 438.65 | 35.60 | 0.63 % | 424 ms | toggles, segmented control thumb, badges |
| `PANEL` | 0.45 | 0.08 | 0.92 | 194.96 | 25.69 | 0.06 % | 610 ms | sidebar/inspector show-hide, sheets, dock panel moves |
| `SMOOTH` (Apple default) | 0.50 | 0 | 1.00 | 157.91 | 25.13 | 0 % | 734 ms | large surfaces, window-level transitions |
| `TRACK` | 0.15 | 0.14 | 0.86 | 1754.6 | 72.05 | 0.5 % | 210 ms | values chasing the pointer (magnetic snapping, scrub) |
| `THROWN` | 0.45 | 0.20 | 0.80 | 194.96 | 22.34 | 1.5 % (analytic) | not probed | only after a drag release with velocity toward the target |

Duration-based (non-interruptible) fallbacks only for one-shot, non-retargetable effects. gpui-component `MotionTokens` already defines fast 120 / normal 180 / slow 280 ms, enter `cubic-bezier(0.16,1,0.3,1)`, exit `(0.4,0,1,1)`, move `(0.2,0,0,1)` (`gpui-component-0.7.0/src/theme/motion.rs`). Reuse them; add no fourth set.

Exit is faster than enter: exits run with d × 0.7 (e.g. `UI` exit 0.25 s). "Dismiss" should never be slower than "present" (HIG brevity).

### 3.2 `AnimatedValue` — the one new primitive (sketch)

Compiled clippy-clean in the probe under `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::indexing_slicing)]`. The spring is Copy state inside the owning view entity. It is advanced with the same gpui solver and drives frames through `request_animation_frame`. It exists because element-keyed state dies on unmount and cannot take an initial velocity.

```rust
// dial-ui/src/motion.rs — no unwrap/expect/indexing; f32 math is non-integer so no overflow lints.
use gpui_kit::{SpringConfig, SpringState, Window};
use std::time::Instant;

#[derive(Clone, Copy, Debug)]
pub struct AnimatedValue {
    config: SpringConfig,
    state: SpringState,
    target: f32,
    epsilon: f32,
    last: Option<Instant>,
}

impl AnimatedValue {
    pub const fn new(value: f32, config: SpringConfig, epsilon: f32) -> Self {
        Self { config, state: SpringState { position: value, velocity: 0.0 }, target: value, epsilon, last: None }
    }
    /// Retarget; position and velocity are kept (interruptible).
    pub fn set_target(&mut self, target: f32) { self.target = target; }
    /// Hand-off from a gesture: keep the finger's velocity (px/s).
    pub fn release(&mut self, target: f32, velocity: f32) { self.target = target; self.state.velocity = velocity; self.last = None; }
    /// 1:1 tracking while dragging.
    pub fn track(&mut self, value: f32) { self.state = SpringState { position: value, velocity: 0.0 }; self.target = value; self.last = None; }
    /// Call from `render`; returns the presentation value and schedules the next frame if moving.
    pub fn sample(&mut self, reduce_motion: bool, now: Instant, window: &mut Window) -> f32 {
        if reduce_motion { self.state = SpringState { position: self.target, velocity: 0.0 }; return self.target; }
        let dt = self.last.map_or(0.0, |t| now.saturating_duration_since(t).as_secs_f32().min(0.064)); // clamp hitches
        self.state = self.config.step(self.state, self.target, dt);
        self.last = Some(now);
        if self.config.is_settled(self.state, self.target, self.epsilon) {
            self.state = SpringState { position: self.target, velocity: 0.0 };
            self.last = None;
        } else {
            window.request_animation_frame();
        }
        self.state.position
    }
    pub fn is_settled(&self) -> bool { self.last.is_none() && self.state.position == self.target }
}
```

Notes:
- Use `cx.background_executor().now()` instead of `Instant::now()` so GPUI's test scheduler can advance the clock, as gpui-base does (`motion.rs:584`). That keeps `#[gpui_kit::test]` deterministic under nextest.
- The dt clamp (64 ms) stops a resumed-from-background window from teleporting.
- `is_settled` gives unmount-after-exit ("Presence with a spring").
- The reduced-motion fade variant is a second `AnimatedValue` on opacity using `MICRO` with a translate multiplier of 0. Keep the policy in one `MotionPolicy` global read via `try_global`.

### 3.3 Other small pieces dial-ui owns
- `Offset` element: `Element` whose `prepaint` wraps the child in `window.with_element_offset(offset, |w| child.prepaint(w, cx))`. Layout is untouched, so slide motion costs paint only. Must be keyed by element id and non-panicking: handle `Option<&GlobalElementId>` with `let … else`, unlike upstream's `global_id.unwrap()`.
- `VelocityTracker` for mouse drags. Keep the last 100 ms of samples and fit the velocity the way gpui's touch tracker does (`gestures.rs:1018-1091`, private, so re-implement).
- `SystemPrefs` global: accent color, reduce transparency, increase contrast. Refreshed on window activation and appearance change; Linux follows portal signals through a detached `cx.spawn` like gpui-base's reduce-motion follower. No `unsafe` in dial: every call listed in §3.1 is a safe fn in `objc2-app-kit 0.3.2` / `windows 0.62` / `ashpd 0.13`. Direct target-specific deps on these crates are *reuse* of crates already in the graph (dep-review + deps.md row still required). Pin `windows = "0.62"`, matching gpui-pre-windows, not gpui-base's 0.58.

## 4. Platform notes (materials, titlebar, text)

### 4.1 macOS (15+)
- Titlebar: `appears_transparent: true`, `traffic_light_position: Some(point(px(14.), px(12.)))` [proposal], with gpui-component `TitleBar` providing the drag area.
- Material: `Blurred` gives a whole-window behind-window blur (material `Selection`). Paint content panes opaque and leave the sidebar at 70–80 % alpha over it. Under Reduce Transparency, force `Opaque`.
- No Liquid Glass. `NSGlassEffectView` exists in `objc2-app-kit 0.3.2` (`generated/NSGlassEffectView.rs`), but inserting it into GPUI's `NSView` needs the raw window handle cast, i.e. `unsafe` in dial plus a workspace `unsafe_code` exemption for one `dial-platform` crate. Not recommended; track upstream.
- Text: CoreText, grayscale AA (the OS has had no subpixel AA since 10.14 [UNVERIFIED for 26]).

### 4.2 Windows (10/11, MSVC)
- Material: `MicaBackdrop` on Win 11 ≥ 22621, else Opaque. Don't use `Blurred`: it relies on the undocumented acrylic accent API; drag lag reports [UNVERIFIED].
- Titlebar: custom, with `window_control_area(Max)` on the maximize button so the Win 11 snap-layout flyout works.
- Text: DirectWrite with the default rendering mode. Offer Grayscale as a setting for users on rotated/OLED panels.
- Accent: `UIColorType::Accent`.

### 4.3 Linux (Wayland + X11)
- Material: Opaque by default. `Blurred` works only on KDE; GNOME has no blur protocol. Don't design anything that relies on translucency.
- Decorations: GNOME Wayland needs CSD. Request `WindowDecorations::Client` and use `TitleBar`'s Linux controls plus resize edges via `start_window_resize`.
- Text: cosmic-text/swash. Bundling fonts matters most here (gpui-component notes `.SystemUIFont` maps to a family most desktops lack).

## 5. Design language proposal (five-year horizon)

**Stance.** A quiet, dense, keyboard-first instrument, not a website. Draw from:
- Linear: restraint, LCH/OKLCH-generated themes from 3 inputs (base, accent, contrast), Inter + Inter Display, reduced chrome noise.
- Raycast: command palette as the primary navigation surface, instant response.
- Zed: native-speed text, hairline dividers, CSD titlebar that holds tabs.
- Warp: blocks as the unit of terminal output. It maps onto agent turns and runs.
- Arc/Dia: calm sidebar-as-workspace, translucent chrome over opaque content.
- Things 3: exceptional micro-typography, generous hit targets, spring motion used sparingly.
- Apple Liquid Glass: a functional layer floats over content, content stays opaque.

The shared thread across all of these is that content is opaque and calm while chrome is light and tertiary. They also share one accent color, motion as feedback rather than decoration, and zero perceived latency. That combination is what keeps a design from dating: trendy textures (heavy glass, gradients, glows) are what ages.

### 5.1 Color (OKLCH-authored, converted to `Hsla` at theme load)
- GPUI has no OKLCH type (only an `Oklab` interpolation space, `color.rs:763`, and gpui-component `mix_oklab`). Author tokens as `oklch(L C H)` in the theme JSON. Convert with a ~25-line OKLCH→linear sRGB→sRGB→`Hsla` fn in dial-ui, gamut-clamping chroma. Don't add a color crate; `palette 0.7.7` would be a new category for ~25 lines of math.
- Generator inputs: `base_hue` (default 265, a cool neutral), `accent` (default `oklch(0.66 0.17 258)`, or the system accent), `contrast` (0–100).
- Proposed dark ramp (neutral chroma 0.006–0.012):
  - bg `0.17`
  - sidebar `0.19`
  - surface/panel `0.205`
  - elevated (popover, palette) `0.235`
  - hover `+0.03 L`
  - selected = accent at 18 % alpha
  - border `0.28` (hairline 1 px, 0.5 px on 2× displays)
  - text `0.95`, secondary `0.74`, tertiary `0.58`, disabled `0.45`
- Proposed light ramp:
  - bg `0.985`
  - sidebar `0.965`
  - surface `1.0`
  - elevated `1.0` + shadow
  - border `0.90`
  - text `0.22`, secondary `0.45`, tertiary `0.58`
- Status hues at matched lightness (dark L 0.72 / light L 0.55): success 150, warning 80, danger 25, info 235; C ≈ 0.14.
- Agent-state colors: a separate 6-hue categorical set at equal L/C, so agents are distinguishable without any one shouting.
- Contrast: body text ≥ 4.5:1 (WCAG 2.2 AA), secondary ≥ 3:1. The `contrast` input raises text L and borders when the OS "increase contrast" flag is on.

### 5.2 Typography
- **UI: Inter 4.1** (rsms/inter, OFL-1.1, latest release v4.1 2024-11-16, ~19.9k★). Bundle static Regular/Medium/SemiBold. Enable `cv11` (single-storey a) off, and `tnum` for counters/timestamps via `FontFeatures`.
  - Rationale: identical metrics on all three OSes. Density and truncation behave the same everywhere, and it's the de facto modern UI face.
  - Risk: ubiquity can read as generic. Mitigate with the Display cut for headings (Linear uses Inter Display).
- **Mono: JetBrains Mono 2.304** (OFL-1.1, release 2023-01-14, ~13k★). Complete box-drawing/Powerline coverage and hinted TTFs, which matter for the libghostty-vt terminal renderer and for Windows at 12–13 px.
  - Alternative: **Geist Mono** (vercel/geist-font, OFL-1.1, v1.7.2 2026-06-01, active). Geist's box-drawing and hinting quality is [UNVERIFIED]. A/B in the terminal before choosing.
- Ship font binaries **unmodified** and under their original names. OFL Reserved Font Names forbid renamed derivatives: Zed had to drop "Zed Plex" for this reason (zed PR #36084).
- Scale (px, UI at 1×):
  - 11/14 caption
  - 12/16 small/meta
  - **13/18 body (default, macOS standard)**
  - 15/20 emphasized
  - 18/24 title
  - 24/30 display
  - mono 12.5/18 transcript code, terminal 13 default
  - weights 400 / 500 (labels) / 600 (titles). Never 700 in chrome.

### 5.3 Space, shape, elevation, density
- 4 px grid: 2, 4, 6, 8, 12, 16, 24, 32.
- Control heights 24 (compact) / 28 (default) / 32 (comfortable). Row height 28. Sidebar 240 px default. Density setting switches compact ↔ default only.
- Radius: 4 (chips, inputs), 6 (buttons, rows), 8 (cards, popovers), 12 (dialogs, palette, windowed sheets); full for pills/avatars. Nested radius = outer − padding.
- Elevation (3 levels only):
  - e1 hairline border, no shadow
  - e2 (popover/menu): border + `0 4 12 −2 / 12 %` + `0 1 3 / 8 %`
  - e3 (dialog/palette): border + `0 16 40 −8 / 24 %` + `0 2 6 / 10 %`
  - Dark mode relies on a lighter surface + 1 px top highlight (`oklch(1 0 0 / 6 %)`) more than on shadow.
- Materials: translucency only on sidebar/titlebar/palette backdrop scrim (black 30 % dark / 12 % light). Never under body text without an opaque fallback.

### 5.4 Iconography
- Lucide (ISC license; `lucide-icons/lucide` 1.48.0, 2026-09-24, very active) via `gpui_kit::assets` / `IconName`. 16 px in rows/toolbars, 14 px inline, stroke 1.5.
- Icons inherit text color tokens. Accent tint only for the active/selected state.
- Agent/provider logos are the only multicolor icons.

### 5.5 Interaction
- **Keyboard-first:**
  - Every action is a GPUI `Action`, reachable from the command palette (gpui-component `Command`).
  - `secondary-k` palette, `secondary-p` quick switch, `secondary-shift-p` all commands.
  - Shortcut hints (`Kbd`) are visible in menus and tooltips.
- **Focus:** a 2 px accent ring at 2 px offset via `focus_visible`, never removed. Mouse clicks don't show rings.
- **Hit targets:** ≥ 24×24 px (WCAG 2.2 target size), ≥ 28 px for primary.
- **Feedback latency budget:**
  - key/mouse → first visual change on the **next frame** (≤ 8.3 ms at 120 Hz, ≤ 16.7 ms at 60 Hz)
  - hover tint ≤ 1 frame (no animation delay on hover-in; `MICRO` spring on hover-out only)
  - palette open → results rendered within 1 frame for cached items, ≤ 50 ms for fuzzy search over 10k items (off-thread)
- **Streaming text:** at most one `cx.notify()` per frame for a transcript (cap 33 ms), `TextView` stream fade on. The transcript never re-lays-out earlier messages (virtualized `MessageScroller`).
- **Terminal (libghostty-vt):** content never animates. Cursor blink is the only loop: 530 ms on / 530 ms off [proposal], disabled under Reduce Motion. Selection highlight is instant.

## 6. Draft rule text for `.omp/rules/ui-design-motion.md`

```markdown
---
description: dial UI design + motion rules (tokens, springs, reduced motion, frame budgets) — read before writing UI code
globs: ["crates/dial-ui/**/*.rs", "apps/dial/**/*.rs"]
---

# dial UI design & motion

## Tokens only
- Colors, spacing, radii, shadows, font sizes, durations and springs come from `dial_ui::tokens` / the active theme. No literal `rgb(..)`, `hsla(..)`, `px(..)` sizes, or `Duration::from_millis` in views (exceptions: 0 and 1 px hairlines).
- Colors are authored in OKLCH in the theme and converted once at load; never build colors in `render`.
- Fonts: bundled Inter (UI) + JetBrains Mono (code/terminal), registered with `text_system().add_fonts(..)?` before the first window. Name families explicitly — GPUI panics on a missing family.

## Motion = springs from the preset table
- Anything the user can re-trigger mid-flight (open/close, select, reorder, resize, show/hide) uses a spring: `gpui_kit::base::spring`, `.with_spring(..)`, or `dial_ui::motion::AnimatedValue`. Never a duration curve.
- Only presets: `MICRO, UI (default), SNAPPY, PANEL, SMOOTH, TRACK, THROWN`, declared as `const` (invalid literals fail at compile time). Parameterise as Apple does: perceptual duration + bounce; `Spring::new(d).with_damping(1.0 - bounce)`.
- Bounce > 0 only when a gesture's release velocity points toward the target; never above 0.3.
- Retarget, never restart: keep position and velocity. Seed from gesture velocity with `AnimatedValue::release(target, v)`.
- Dragging tracks 1:1 (`with_travel(false)` / `AnimatedValue::track`); springs resume on release.
- Exits run at ~0.7× enter duration; dismiss is never slower than present.
- Duration animations (`Animation`, `Transition`) only for loops and one-shot decoration; loops use `.with_max_fps(30.)` unless they convey progress.
- Motion state that must survive unmount, virtualization, or a skipped frame lives in the view entity (`AnimatedValue`), not in element-keyed state.
- Use `cx.background_executor().now()` for animation clocks (deterministic tests).

## Don't animate
- Layout properties (`w/h/top/left/margin/padding/gap`, flex changes). Animate `opacity` and paint offset (`dial_ui::motion::Offset`, `with_element_offset`). Size changes use `MotionReveal`, clipped, once.
- Terminal content, typed text, selections, scrolling content itself, re-sorts of >50 rows, anything while idle.
- Travel stays short: enter/exit offsets 4–8 px; no scale on text-bearing surfaces; no blur transitions.

## Reduced motion
- Respect `cx.reduce_motion()` everywhere; read it through `MotionPolicy`. Re-apply the OS setting on window activation (`apply_system_reduce_motion`).
- Reduced = no translate/scale/bounce/parallax/loops; replace movement with a ≤150 ms opacity fade; gestures stay 1:1.
- Reduce Transparency → opaque window + opaque surfaces. Increase Contrast → contrast token up.

## Frame budget (60/120 Hz)
- While anything animates, main-thread render+layout+paint ≤ 4 ms per frame (120 Hz) and ≤ 8 ms (60 Hz). Profile with `gpui-kit` `profiler` feature before merging new motion.
- `window.request_animation_frame()` re-renders the whole current view: isolate animated parts in small child entities.
- Stop requesting frames the moment a value settles; no timers or frame loops for static UI.
- Streaming: at most one `cx.notify()` per frame per transcript (≤33 ms coalescing); heavy parsing via `background_spawn`.
- Input → first visual response on the next frame; no artificial delays except tooltips.

## Interaction
- Every command is an `Action`, listed in the command palette with its key binding.
- Every focusable element shows a 2 px `focus_visible` ring; never remove focus styling.
- Hit targets ≥ 24×24 px.
- Materials: opaque by default; translucency only on chrome (sidebar/titlebar/palette scrim) via `WindowBackgroundAppearance` (macOS `Blurred`, Win11 `MicaBackdrop`, Linux Opaque).
```

## 9. Open risks
- gpui-kit ships weekly pre-1.0 releases. The motion APIs (`Spring`, `spring`, `SpringAnimation`, `MotionTokens`) are young, and `motion.rs` itself distinguishes a "legacy" `animation::Transition`. Pin `=0.7.0` and wrap them behind `dial_ui::motion` so upgrades touch one module.
- Built-in Dialog/Sheet/Popover have no exit motion and animate layout props. Visual inconsistency with dial's own springs until upstreamed or wrapped.
- Windows/Linux high-refresh pacing, Mica appearance, and KDE blur are unmeasured here (no hardware).
- Upstream library code keeps internal `unwrap`/`expect` (`animation.rs:270,344`, `reveal.rs:56`). They are unreachable by construction, but dial's own `Offset` element must not copy the pattern.
- The Inter-everywhere choice trades native feel (SF Pro / Segoe UI Variable) for cross-platform consistency. Revisit if macOS users report "non-native" feel. Apple's SF Pro license forbids bundling, so the only native option on macOS is `.SystemUIFont`.
- The "one notify per frame" streaming change conflicts with the current `gpui-patterns` rule (~100 ms). Needs a main-agent decision.
