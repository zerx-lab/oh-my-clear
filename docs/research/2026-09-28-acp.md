# Agent Client Protocol (ACP) for `dial` (researched 2026-09-28)

**What was read:** shallow clones of `agentclientprotocol/agent-client-protocol` (HEAD 2026-09-27; `schema/v1|v2/meta*.json`, `schema.json`, `docs/protocol/v1|v2/*.mdx`, `docs/rfds/*.mdx`, `CHANGELOG.md`), `agentclientprotocol/rust-sdk` (HEAD 2026-09-24), and `agentclientprotocol/registry` (HEAD 2026-09-28, including `.protocol-matrix/latest.md` dated 2026-09-27). I also read the live `registry.json` CDN file, the crates.io API, RustSec `advisory-db`, Zed's `crates/project/src/agent_registry_store.rs` and `agent_server_store.rs` (main branch), and Zeron's `docs/research/acp.md`.

**What was run:** a live `initialize` probe (Python, ndjson over stdio) against `claude-agent-acp@0.81.2`, `codex-acp@1.13.1`, `gemini-cli@0.61.0`, `qwen-code@0.24.6`, `@github/copilot@1.0.88` (all through `npx`), and the locally installed `omp acp` (18.4.0). I also ran `cargo tree` on a throwaway crate for both Rust crates.

## 0. Recommendations (TL;DR)

1. **Protocol target: ACP v1 (`protocolVersion: 1`), and design for v2 now.**
   - v1 is the only stable version. v2 exists as a *draft* (JSON schema `2.0.0-alpha.5`, behind the `unstable_protocol_v2` feature). The spec says to negotiate per connection and keep v1 working ([migration](https://agentclientprotocol.com/protocol/v2/migration)).
   - v2 removes the client `fs/*` and `terminal/*` methods, removes `session/set_mode` and `session/load`, and turns updates into upserts keyed by ID.
   - So dial's internal `AgentEvent` should be **upsert-by-id**: `messageId`, `toolCallId`, `planId`, plus an explicit turn state (`running`/`idle`/`requires_action`). Modes should be **config options**.
2. **Crate: `agent-client-protocol-schema = { version = "=1.9.1", default-features = false, features = ["unstable_session_fork"] }` plus dial's own tokio JSON-RPC ndjson driver.**
   - Do **not** use the `agent-client-protocol` 2.2.0 SDK. It unconditionally pulls `async-io`, `async-process`, `blocking`, and `async-signal` on non-wasm targets (verified with `cargo tree`), which is a second runtime ecosystem.
   - The same driver serves both roles: dial as a client of third-party agents, and `dial acp` exposing the native agent to Zed/JetBrains.
   - This confirms the "Open" item in ADR 0005.
3. **Registry and install:**
   - Consume the official registry at `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`: fetch at most once an hour, cache the last good copy, and ship a bundled fallback snapshot.
   - The **daemon** (a single writer) installs each agent **once** into a versioned, atomically committed directory and launches it directly (`node <bin.js>` or the native executable). It never uses `npx` in the hot path.
   - Pin exact versions in a dial-owned lock. Updates are explicit or background-prefetched and switch only at a session boundary.
   - Node ≥ 22 is needed for about half the catalogue. Detect system Node, otherwise offer a managed, sha256-verified Node.
   - `uvx` entries appear only if `uv` is on PATH.
4. **MCP injection (dial orchestration tools into third-party sessions):**
   - **Primary:** the daemon hosts a loopback **streamable-HTTP MCP endpoint** with a **per-session bearer token** in `McpServerHttp.headers`. Use it only when the agent advertises `mcpCapabilities.http` (all six agents probed do).
   - **Fallback:** a stdio proxy (`dial mcp-proxy --session <id>`, same executable) that bridges to the daemon over its local IPC socket or named pipe. stdio is the only MCP transport every v1 agent MUST support.
   - One rmcp tool implementation sits behind both.
   - Track **MCP-over-ACP** (`"type": "acp"`, draft RFD, `unstable_mcp_over_acp`) as the eventual zero-endpoint option.
5. **Auth UI:** support both spec method types:
   - `agent`: call `authenticate`; the agent opens a browser.
   - `terminal`: re-launch the same agent command with the method's `args`/`env` in a dial PTY rendered by libghostty-vt, then reconnect.
   - Also handle three *legacy extension* shapes seen in the wild: `_meta["terminal-auth"]`, `_meta.type = "terminal"`, and `_meta["api-key"]`.
   - Advertise `clientCapabilities.auth.terminal = true`.
   - Auth is interactive, so while the UI is detached the daemon parks the session in a "needs sign-in" state.

## 1. Protocol: version, methods, capabilities

### 1.1 Versions and releases
- The wire protocol version is a single integer major. The client sends its latest version; the agent echoes it or answers with its own latest. The client SHOULD disconnect if it can't speak the agent's answer ([initialization](https://agentclientprotocol.com/protocol/v1/initialization)).
- **v1 is stable.** Its JSON schema artifact is `schema-v1.23.0` (2026-09-18), and the Rust type crate is `agent-client-protocol-schema` 1.9.1 (2026-09-18). The repo's 1.0.0 release was 2026-06-24 (`CHANGELOG.md`).
- **v2 is a draft.** Artifact `2.0.0-alpha.5`, crate feature `unstable_protocol_v2`, deliberately excluded from the `unstable` umbrella feature. The migration guide says "gate v2 support behind explicit version negotiation and feature flags until it stabilizes" ([v2 migration](https://agentclientprotocol.com/protocol/v2/migration)).
- All 34 agents that initialized successfully in the registry's 2026-09-27 matrix answered `protocolVersion: 1` (`.protocol-matrix/latest.json`). The six live probes also answered 1.

### 1.2 Transport
stdio carries newline-delimited JSON-RPC 2.0. Messages MUST NOT contain embedded newlines, `stderr` is free-form logging, and stdout must carry only ACP messages ([transports](https://agentclientprotocol.com/protocol/v1/transports)). Streamable HTTP/WebSocket is an *Active* RFD, not part of the spec (`docs/rfds/streamable-http-websocket-transport.mdx`).

Error codes (`ErrorCode` in the schema): the JSON-RPC standard set, plus `-32800` request cancelled, **`-32000` authentication required**, and `-32002` resource not found.

### 1.4 `session/update` variants
- **Stable v1 (`schema.json`):** `user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`, `plan`, `available_commands_update`, `current_mode_update`, `config_option_update`, `session_info_update`, `usage_update`.
- **Unstable additions:** `plan_update`, `plan_removed`, `notice`, `compaction_update`, `compaction_summary_chunk`.
- **ToolCall** fields:
  - `toolCallId`, `title`, `name` (stabilized in 1.8.0), `kind`, `status`, `content[]`, `locations[]`, `rawInput`, `rawOutput`.
  - `kind` ∈ `read`, `edit`, `delete`, `move`, `search`, `execute`, `think`, `fetch`, `switch_mode`, `other`.
  - `content` items are `content`, `diff` (`path`, `oldText`, `newText`), or `terminal` (embeds a client terminal id).
  - `locations` are `{path, line}`, used for follow-along.
- **Plan** entries carry content, priority, and status ([agent-plan](https://agentclientprotocol.com/protocol/v1/agent-plan)).
- **Available commands** are slash commands with an optional input hint ([slash-commands](https://agentclientprotocol.com/protocol/v1/slash-commands)).
- **Config options** are `select` or `boolean` types. Boolean options require `clientCapabilities.session.configOptions.boolean`. `category` ∈ `mode`, `model`, `model_config`, `thought_level`. **Model selection = a config option with category `model`.** ACP has no per-prompt model field; Zeron applies model and effort via `session/set_config_option`.
- **`usage_update`:** `used`, `size` (context window), `cost`.
- **v2 changes:** chunks require `messageId`; whole-message upserts are added; `tool_call` is dropped (the first `tool_call_update` creates the call); `tool_call_content_chunk` is added; `plan` becomes `plan_update`; `current_mode_update` becomes a config option ([v2 migration table](https://agentclientprotocol.com/protocol/v2/migration)).

### 1.5 Capability flags (v1)
- **Client (`clientCapabilities`):** `fs.readTextFile`, `fs.writeTextFile`, `terminal` (bool), `auth.terminal` (bool), `elicitation.{form,url}`, `session.configOptions.boolean`, `_meta`.
- **Agent (`agentCapabilities`):**
  - `loadSession`
  - `promptCapabilities.{image,audio,embeddedContext}` (text and `resource_link` are the baseline)
  - `mcpCapabilities.{http,sse}` (SSE is deprecated by MCP), plus unstable `acp`
  - `sessionCapabilities.{list,resume,close,delete,additionalDirectories}` and unstable `fork`
  - `auth.logout`
  - `_meta`
- The baseline every agent MUST support: `session/new`, `session/prompt`, `session/cancel`, `session/update`.
- Omitted capabilities MUST be treated as unsupported ([initialization](https://agentclientprotocol.com/protocol/v1/initialization)).

### 1.6 MCP servers in session setup
- `session/new`, `session/load`, and `session/resume` all take `mcpServers[]` (plus `cwd`, `additionalDirectories`).
- Server types:
  - stdio: `{name, command, args, env[]}`, no `type` field
  - `{"type":"http", name, url, headers[]}`
  - `{"type":"sse", …}`
  - unstable `{"type":"acp", …}`
- "All Agents **MUST** support the stdio transport … new Agents **SHOULD** support the HTTP transport" ([session-setup § MCP servers](https://agentclientprotocol.com/protocol/v1/session-setup)).
- In v2, stdio also becomes an explicit capability (`session.mcp.stdio`) and SSE is dropped.

### 1.7 Extensibility
- `_meta` on most types. The root keys `traceparent`, `tracestate`, and `baggage` are reserved for W3C trace context.
- Implementations MUST NOT add custom root fields to spec types.
- Custom requests and notifications use method names starting with `_`. Unknown requests get `-32601`; unknown notifications SHOULD be ignored.
- Extensions are advertised through `_meta` in capability objects ([extensibility](https://agentclientprotocol.com/protocol/v1/extensibility)).
- v2 additionally makes every enum and union accept unknown values.

**Extensions observed in live `initialize` responses (2026-09-28):**
- `claude-agent-acp` 0.81.2 and `codex-acp` 1.13.1: `_meta.authStatus`, non-spec `sessionCapabilities.subagents` and `agentCapabilities.providers`.
- `claude-agent-acp`: `_meta.claudeCode.promptQueueing`.
- Zeron documents `_session/steering` gated on `initialize._meta.steering`.

dial's decoder must be tolerant. The schema crate helps here: fields carry `x-deserialize-default-on-error`, and the crate has `VecSkipError`.

### 1.8 Client-side terminals: what agents actually use
- **Spec:** `terminal/create {sessionId, command, args, env, cwd, outputByteLimit}`, then `terminal/output → {output, truncated, exitStatus}`. The client truncates output at a character boundary. An embedded terminal keeps displaying after release ([terminals](https://agentclientprotocol.com/protocol/v1/terminals)).
- **Practice (grepped the installed npm dist):** `claude-agent-acp` 0.81.2 never calls `terminal/create`. It runs Bash itself and streams output through a `_meta.terminal_output` / `_meta.terminal_output_delta` extension on tool-call updates, but only when the client sets `clientCapabilities._meta.terminal_output(_delta) = true`. `codex-acp` 1.13.1 contains the method table and `createTerminalOutputMeta` but no call site for `createTerminal(`.
- **Implication for dial:**
  - Implement v1 `terminal/*` backed by dial's PTY and libghostty-vt. It is cheap and some agents use it; which ones is [UNVERIFIED].
  - More importantly, render the `_meta.terminal_output_delta` byte stream (and v2's `terminal_output_chunk`) through the same libghostty-vt surface. That is where most agent shell output will come from.
- The v2 rationale: client fs/terminal "was inconsistently implemented outside of a few IDEs"; clients should expose such tools "by providing" MCP servers instead ([v2 migration § client surface](https://agentclientprotocol.com/protocol/v2/migration)).

## 2. Registry and discovery

### 2.1 Format and URLs
- **Official registry:** repo `github.com/agentclientprotocol/registry` (409★, pushed 2026-09-28). Completed RFD: [acp-agent-registry](https://agentclientprotocol.com/rfds/acp-agent-registry).
- **Index:** `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`. JetBrains has its own variants, `registry-for-jetbrains.json` and `registry-for-jetbrains-preview.json` ([registry README](https://github.com/agentclientprotocol/registry)). Each build also publishes a versioned GitHub release, so a snapshot can be pinned.
- **Entry fields** (`FORMAT.md`): `id`, `name`, `version`, `description`, `repository`, `website`, `authors`, `license`, `license_url`, `icon` (16×16 SVG using `currentColor`), and `distribution`.
- **Distribution kinds:**
  - `binary`: per-platform `{archive, sha256?, cmd, args, env}` keyed `darwin-aarch64|darwin-x86_64|linux-aarch64|linux-x86_64|windows-aarch64|windows-x86_64`. Archives are .zip/.tar.gz/.tgz/.tar.bz2/.tbz2 or a raw binary; installers are not supported.
  - `npx`: `{package: "name@version", args, env}`.
  - `uvx`: `{package, args}`.
  - The `preview` channel is npx/uvx only, is unverified, and appears only in the JetBrains preview index.
- **Maintenance:** versions are bumped hourly by cron (npm, PyPI, GitHub releases). Admission requires `agent` or `terminal` auth, and CI verifies `authMethods` ([AUTHENTICATION.md](https://github.com/agentclientprotocol/registry/blob/main/AUTHENTICATION.md)). `quarantine.json` lists broken agents (7 today).
- **Live index 2026-09-28:** 41 agents; 22 npx, 19 binary, 2 uvx (kilo and sigit ship both binary and npx). `sha256` is present on only 10 of the 19 binary entries.
- **Daily protocol matrix** (`.protocol-matrix/latest.md`, 2026-09-27): 35 agents probed; 34 `initialize` OK; 22 returned `auth_required` on `session/new`; `session/list` supported by 22, `session/resume` by 12, `session/fork` by 9. This makes it a free compatibility oracle dial can surface in its agent picker.

### 2.2 How Zed and JetBrains consume it
- **Zed** (`crates/project/src/agent_registry_store.rs`, `agent_server_store.rs`):
  - Fetches the registry URL with a 30 s timeout, throttled to 1 h. It caches `registry.json` under `external_agents/registry/`.
  - Supports only `Binary` and `Npx` (no uvx).
  - Npx install: `npm install <pkg>@"0.0.0 - <ver>" --save-exact` into `external_agents/registry/npx/<id>`, using a version ceiling because of npm `min-release-age` ([zed#53309](https://github.com/zed-industries/zed/issues/53309)). It launches `node <package bin>`, not `npx`, and uses Zed's managed Node runtime. The hyphen range avoids `cmd.exe` treating `<` as redirection on Windows (zed#55921).
  - Binary install: extracts into `v_<hash(url,sha256)>` directories. It fills in a missing `sha256` from the GitHub release asset digest and removes stale version directories.
- **Known Zed failure modes worth designing out:**
  - Concurrent installs from multiple windows hang ([#63743](https://github.com/zed-industries/zed/issues/63743)).
  - npm cache grew to 10–17 GB, fixed by clearing it on startup ([PR #61750](https://github.com/zed-industries/zed/pull/61750)).
  - npm packages whose `bin` is a native executable crash under `node <bin>` ([#64429](https://github.com/zed-industries/zed/issues/64429), [#62716](https://github.com/zed-industries/zed/issues/62716)).
  - Users asked Zed to prefer a binary already on PATH ([#49918](https://github.com/zed-industries/zed/issues/49918)) and to make updates optional and non-blocking ([#60814](https://github.com/zed-industries/zed/issues/60814)).
- **JetBrains** uses `registry-for-jetbrains.json`. The build script excludes `github-copilot-cli`, marks `claude-acp` as `bundled: true`, and appends `--hide-claude-auth` to its args (`.github/workflows/build_registry.py`). Details of the JetBrains client-side installer are [UNVERIFIED].

### 2.3 Zeron's move off `npx` (why)
From Zeron `docs/research/acp.md` § "Managed adapter installs (2026-08-15)":
- `npx -y <pinned>` put npm state in the chat hot path. npm reports fatal fs errors as `256 - errno` exit codes (254 = ENOENT, 243 = EACCES; npm/cli#4838), often with no stderr.
- A cold `npx` could stall a first chat for minutes (claude-agent-acp's dependency tree is about 570 MB).
- Zeron now installs once into `~/.zeron/adapters/<pkg>/<version>`, with a Zeron-owned npm cache. The install is atomic: temp dir, then bin-entry verification, then an `.zeron-install-ok` marker, then rename. It launches `node <entry>`, prewarms at boot, and bounds the handshake at 120 s.

My own measurement: the `npx` caches for claude-agent-acp and codex-acp were 263 MB and 342 MB.

### 2.4 Recommended install design for dial
- **Owner:** the daemon only (one writer). The UI requests an install and observes progress events. This removes Zed's multi-window race by construction.
- **Layout** (under the platform data dir, e.g. `…/dial/agents/`; `DIAL_AGENTS_DIR` overrides):
  ```text
  registry/registry.json            # last good fetch + ETag; bundled snapshot fallback; refresh ≤ 1/h
  registry/matrix.json              # optional: .protocol-matrix/latest.json for UI hints
  npm/<agent-id>/<version>/         # npm install --prefix … --save-exact; .dial-install-ok marker
  bin/<agent-id>/<version>-<sha16>/ # extracted archive; sha256 verified when provided
  runtime/node/<node-version>/      # managed Node (only if no system Node ≥ 22)
  cache/npm/                        # dial-owned npm cache, wiped at daemon start
  agents.lock                       # id → {version, kind, sha256|integrity, installed_at}
  ```
- **Resolution order:** user override command → binary already on PATH with the registry's `args` (opt-in, as in zed#49918) → installed pinned version → install.
- **Pinning and updates:** the lock pins the exact version. A newer registry version produces an "update available" event. The daemon prefetches in the background, and new sessions pick up the switch; live sessions and `session/load` of existing sessions stay on their version. Keep N-1 for rollback. After install, run `initialize` once to cache capabilities and auth methods without needing auth.
- **npm specifics:**
  - Resolve the package's `bin` target. If it is not a JS file (a shebang-less native binary, as with grok and droid), exec it directly instead of `node <bin>`.
  - On Windows, never go through `npm.cmd`/`npx.cmd` for launch. Invoke `node.exe <npm-cli.js>` for installs, as Zed does.
  - Surface npm's errno exit codes decoded.
- **Node requirement:** `claude-agent-acp` declares `engines.node >=22`; `gemini-cli` declares `>=20` (npm metadata, 2026-09-28). 22 of 41 registry agents are npx. Recommend requiring Node ≥ 22 from the system, with an optional managed download (nodejs.org dist + `SHASUMS256.txt`). Scoping managed Node is [UNVERIFIED] effort.
- **uvx:** list only if `uv` is on PATH (2 agents). Zed doesn't support uvx at all.

**Schema crate (`agent-client-protocol-schema` 1.9.1):**
- Deps: `serde` (rc), `serde_json` (`preserve_order`, `raw_value`), `serde_with`, `strum` 0.28, `derive_more` 2, `anyhow`; `schemars` optional (default-on); `tracing` optional.

- `cargo check` with `default-features = false` succeeds on the local toolchain. The resolved graph has 39 unique crates, with no tokio and no async runtime.

**SDK (`agent-client-protocol` 2.2.0):**
- Normal deps include `async-io`, `async-process`, `blocking`, `futures-concurrency`, `rustix`, `shell-words`, and `windows-sys`, gated on `cfg(not(target_family = "wasm"))`, i.e. **unconditional on desktop**.
- `cargo tree` with `default-features = false` resolved 115 unique crates, including `async-io` 2.6.0, `async-process` 2.5.0, `async-signal`, and `blocking` 1.7.0. **tokio is not a dependency; it only appears as a dev-dependency.**
- The core is transport-neutral: `ByteStreams` accepts any `futures::AsyncRead`/`AsyncWrite`, so it *can* run on tokio via `tokio-util::compat`.
- However, `acp_agent.rs` (spawning agents) uses `async_process::Command` and `async_io::Timer`, and `stdio.rs` uses `blocking::Unblock`.
- Result: the smol-family reactor is compiled in and used on those paths. It also owns child lifecycle, which Zeron explicitly wanted to own (StderrTail, SIGTERM→SIGKILL, PATH composition).

**Recommendation:** `agent-client-protocol-schema = { version = "=1.9.1", default-features = false, features = ["unstable_session_fork"] }`, with `tracing` added only if malformed-entry warnings are wanted. Write a dial-owned tokio driver:
- ndjson framing over `tokio::process` stdio, with dial's kill-tree via process-wrap
- pending-request map (id → oneshot), with notifications on an ordered channel
- drain queued notifications before resolving turn completion (Zeron's ordering hazard)
- `$/cancel_request`; `-32601` for unknown `_` methods; tolerant decode
- symmetric for the agent role

Pin with `=` because unstable types change between minors; the crate went 1.6 → 1.9 in two months. Adopt v2 later by enabling `unstable_protocol_v2` on the same crate. Serving the native agent as an ACP agent does not require the SDK either.

## 5. Authentication flows and GUI presentation

**Spec** ([authentication](https://agentclientprotocol.com/protocol/v1/authentication), [auth-methods RFD](https://agentclientprotocol.com/rfds/auth-methods), completed 2026-08-20):
- `authMethods[]` come in the `initialize` response. Type `agent` is the default when `type` is omitted.
- **`agent`:** the client calls `authenticate {methodId}`. The agent runs its own flow (the registry says: local HTTP callback server plus opening the default browser) and returns `{}`.
- **`terminal`:** `{id, name, description, args, env}`. The client re-launches **the same agent program and base launch config**, appends `args`, and overlays `env`. It shows the terminal to the user and waits for exit (0 = success), then **reconnects and re-initializes**. The client MUST NOT call `authenticate` for it. This requires `clientCapabilities.auth.terminal: true`.
- **`logout`** is gated by `agentCapabilities.auth.logout`.
- The unauthenticated signal is error **`-32000`** on `session/new` (22 of 34 agents in the matrix).
- `env_var` was removed from the spec (unstable types dropped 2026-07-27), but the matrix still shows `dirac` and `glm-acp-agent` advertising it.

**Legacy shapes seen live:**
- Copilot: `_meta["terminal-auth"] = {command, args, label}` with an absolute command.
- `claude-agent-acp` emits the same `_meta["terminal-auth"]` shape when the client sets `clientCapabilities._meta["terminal-auth"] = true` (source line `acp-agent.js:1015`).
- Qwen: `_meta = {type: "terminal", args}`.
- codex and gemini: `_meta["api-key"] = {provider}` on agent-type methods.
- Proposed but not in the spec: `get-auth-state` (Draft RFD). claude and codex already expose `_meta.authStatus`.

**GUI presentation for dial:**
1. After install, probe `initialize` and store the auth methods. The agent card shows "Sign in required" as soon as `session/new` returns -32000, rather than failing the run.
2. The sign-in sheet lists the methods by `name` and `description`, in the agent's order.
   - For `agent` type: send `authenticate`, show "Continue in your browser…" with a Cancel button (`$/cancel_request`), and treat the request as long-running (minutes).
   - For methods carrying `_meta["api-key"]`: dial may instead show a secure API-key field and pass the key via env on relaunch. That is an extension; the storage crate (OS keychain) is [UNVERIFIED] and needs its own dep-review.
3. For `terminal` type (and the legacy shapes): the **daemon** spawns the login process in a dial PTY. The UI renders it with libghostty-vt in an inline sheet. On exit 0, restart the ACP child and retry `session/new`; on non-zero exit, keep the sheet open with the output.
4. Because the flow is interactive, a run started while the UI is detached parks in `needs_auth` and raises a notification. It resumes when the user completes sign-in after reattaching.
5. Offer "Sign out" only when `auth.logout` is advertised.
6. Elicitation `url` mode (stable) is the protocol-native path for mid-session OAuth prompts. Advertise `elicitation: {form: {}, url: {}}` once the UI supports review-before-submit.

## 6. Injecting dial's orchestration MCP server into third-party ACP sessions

**Context:**
- Agents are children of the **execution daemon**, which outlives the UI.
- `mcpServers` must be re-sent on every `session/new`, `session/load`, and `session/resume`, so a daemon restart re-issues it with fresh credentials.
- Agents probed for HTTP MCP: claude-agent-acp ✔, codex-acp ✔, gemini ✔, qwen ✔, copilot ✔, omp ✔ (all `mcpCapabilities.http: true`). Across the whole registry this is [UNVERIFIED], because the matrix does not record `mcpCapabilities`.

| Option | How | Pros | Cons |
|---|---|---|---|
| **A. stdio proxy** | `{name:"dial", command:"<dial exe>", args:["mcp-proxy","--session",<id>], env:[{DIAL_MCP_TOKEN}]}`. The proxy relays MCP JSON-RPC to the daemon over its IPC (Unix socket / Windows named pipe) | Works with **every** v1 agent (stdio is MUST). No listening port. OS-permissioned socket | One extra process per agent session (and per subagent if the agent forwards MCP config). Needs a stable absolute exe path (macOS app translocation, Windows paths with spaces). Two hops |
| **B. daemon-hosted HTTP** | Daemon runs a streamable-HTTP MCP server (rmcp `transport-streamable-http-server`) on `127.0.0.1:<random>`, `{type:"http", name:"dial", url:"http://127.0.0.1:<port>/mcp", headers:[{name:"Authorization", value:"Bearer <per-session token>"}]}` | No extra processes. Token → session attribution is direct. Survives UI close naturally. One server for all sessions | Gated on `mcpCapabilities.http`. Loopback is reachable by any local process, so it needs a 256-bit per-session token, Host/Origin validation (the RUSTSEC-2026-0189 class), rmcp ≥ 1.4, and revocation on session close. Some agents may persist or log MCP config including headers [UNVERIFIED] |
| **C. MCP-over-ACP** | `{type:"acp", …}` plus `mcp/message` on the existing ACP pipe | No endpoint and no process. Authorization rides the ACP channel | **Draft RFD**, `unstable_mcp_over_acp`, targets MCP 2026-07-28 only. `codex-acp` explicitly reports `acp:false`. Not deployable today |

**Recommendation:**
- Use **B** when `mcpCapabilities.http` is true, and **A** otherwise.
- Implement the tools once as an rmcp `ServerHandler` in the daemon (rmcp 3.5.0 is tokio-native and has both `transport-io` and `transport-streamable-http-server`). This supersedes ADR 0005's "stdio MCP server" wording.
- Advertise dial's server name consistently (`dial`) so prompts can reference its tools.
- Revisit **C** when the RFD reaches Preview. The RFD's own HTTP adaptation guidance (a loopback listener, a connection-specific bearer credential, "a random port is not authentication") matches option B's security model ([mcp-over-acp RFD](https://agentclientprotocol.com/rfds/mcp-over-acp)).
- For dial's **own native agent**, no MCP hop is needed: the orchestration tools are in-process.

## 7. dial as an ACP **agent** (exposing the native agent)
- A `dial acp` subcommand speaks ACP v1 over stdio for Zed, JetBrains, and other clients. It should be a thin bridge to the daemon, so editor-hosted sessions also survive the editor closing and show up in dial's UI. The Rust SDK's "conductor"/proxy-chain design is prior art ([proxy-chains RFD](https://agentclientprotocol.com/rfds/proxy-chains), Draft).
- **Advertise:** `loadSession`, `sessionCapabilities.{list,resume,close}`, `mcpCapabilities.http`, `promptCapabilities.{image,embeddedContext}`, `configOptions` with `model`/`thought_level` categories, and auth methods (`agent` = "use dial's configured providers", plus `terminal` → `dial acp --login`). Registry admission requires ≥ 1 auth method.
- **Publish** to the registry as a `binary` distribution with `sha256` for all six platform targets. That makes dial installable in Zed and JetBrains with one click.

## Open risks
- **v2 churn.** Adopting v2 early means tracking alpha schema changes. Staying v1-only risks agents eventually defaulting to v2; negotiation keeps v1 working, per the spec's guidance.
- **Unstable `session/fork` types** can change in a minor release, so the exact pin is mandatory.
- **Registry quality.** 9 of 19 binary entries lack `sha256`. Zed backfills from GitHub asset digests, and dial should do the same or warn. The registry may reference versions not yet installable under npm `min-release-age` (zed#53309).
- **Node dependency.** Node ≥ 22 for Claude affects Windows and Linux users without Node. Managed Node adds a download and update surface.
- **Extension sprawl.** `_meta.terminal_output(_delta)`, `terminal-auth`, `authStatus`, and steering are adapter-specific and unversioned. Isolate them in an extension module with probes.
- **MCP revision skew.** The agents' embedded MCP clients may speak different MCP spec revisions. Which revisions rmcp 3.5's server negotiates against each agent is [UNVERIFIED]; smoke-test claude, codex, and gemini against the daemon endpoint.
